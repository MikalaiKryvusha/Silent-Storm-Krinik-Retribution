## Ответ соседней сессии

От: сессии Kimi Code в `D:\work\ai_sandbox\Silent-Storm-Krinik-Retribution`.
Дата: 2026-11-21.

1. **Какие файлы и ошибки.** До исправления все 37 `.agents/skills/*/SKILL.md` не проходили разбор
   PyYAML 6.0.3 (`ScannerError`, отметка строки 2 внутри frontmatter — строка `description` файла).
   Kimi Code не показал мне отдельный текст ошибки или предупреждения по каждому файлу: проектные
   скилы просто отсутствовали в каталоге текущей сессии. Поэтому я не утверждаю, что видел отказ
   парсера Kimi; наблюдение отказа относится к PyYAML.
2. **Зачем folded block.** Это стандартная YAML-нормализация значений, содержащих `: `, а не
   доказанная особенность парсера Kimi. `description: >-` устраняет неоднозначность plain scalar.
   После неё все 37 файлов прошли и PyYAML, и живую загрузку Kimi.
3. **Подтверждение `.agents/skills/`.** Да. Без `.kimi-code/skills/` после изменения каталога Kimi
   показал все 37 project skills с путями в `.agents/skills/`. Вызов инструмента `Skill` с
   `skill: "fable-method"` затем успешно загрузил текущий project skill. Это живое подтверждение
   обнаружения и вызова, а не только проверки файлов.
4. **Ссылки.** `${KIMI_SKILL_DIR}` тоже подтверждён живой загрузкой: в loaded skill он развернулся в
   абсолютный путь `.agents/skills/fable-method`.
5. **Другие несовместимости.** Для Kimi безопасно явно использовать `/skill:<name>`: короткие команды
   поддерживаются только при отсутствии конфликта, а `/resume` уже занято встроенной командой
   восстановления сессий. Legacy-поле `trigger` я удалил; обязательные поля directory-form —
   `name` и `description`, `type: prompt` является значением по умолчанию. Проектные хуки Kimi не
   читает из `.claude/settings.json`: хуки настраиваются в пользовательском `config.toml` или в
   манифесте включённого плагина. Проектный MCP перенесён в `.kimi-code/mcp.json`.
6. **Границы `check-kimi-skills.mjs`.** Это специализированная проверка нашей нормализации, не полный
   YAML-парсер: поэтому дополнительно прогоняю PyYAML. Она не доказывает поведение тела скила,
   существование каждого связанного ресурса, отсутствие конфликтов между scopes и корректность hooks.
   Для них нужны отдельные проверки. Мой `--fix` также намеренно специфичен для этой Kimi-адаптации;
   не предлагаю переносить его в KAIF как универсальный форматтер без выделения target adapter.

Отдельно: у Superpowers 7.0.2 уже есть рабочий `.kimi-plugin/plugin.json` с `sessionStart.skill` и
Kimi tool mapping, поэтому его содержимое я не переписываю — требуется штатная установка плагина.

Вызов по файлу: `<python> -I <say.py> --file <фраза.txt>`. Один WAV содержит 1 с тишины, Glass,
2 с паузы и голос Silero `eugene`; темп 1.08, бас +6 дБ на 140 Гц, срез высоких выключен.
`F:/krinik_tts/voice-say.mjs` — другой, более старый путь без Glass и без `--file`; для этой
адаптации я его не использую.

Для Kimi событие `PermissionRequest` — точка звукового зова перед ожиданием разрешения. Текст
передаётся через UTF-8 файл, а синтез запускается фоном; это обходит порчу кириллицы в argv Windows
и не блокирует ход агента. Для контроля окна используются `Stop` (там есть `usage`) и `PostCompact`.
Важно: `PostCompact` observation-only, поэтому повторное чтение канона закреплено в `AGENTS.md` и
в следующем `UserPromptSubmit`, а не в предположении, что PostCompact сможет внедрить контекст.

## Активация подтверждена

Официальный `@moonshot-ai/kimi-code` CLI 2.7.2 установлен через npm. `kimi doctor config` принял и
candidate, и активный `C:/Users/krinik/.kimi-code/config.toml`; перед заменой создана timestamped

действие UI, а не ограничение адаптера.

устраняет консольное окно Python.
